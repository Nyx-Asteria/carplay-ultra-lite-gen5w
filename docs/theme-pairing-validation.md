## Local implementation audit and timing

CPUL's zygote preflight verifies target and registry API shape, not native activation. HMG-API loads WCP first. CPUL registers synchronously in iAP2 appLoaded before starting the polling observer; a missing provider retries at ~2 s, which may be too late for initial pairing. WCP appLoaded may already have begun native initialization; actual dispatch ordering unverified. Do not move registration to global zygote or add a blocking readiness dependency without provider lifecycle evidence. New fixed log markers initial contribution attempt/confirmed/unconfirmed/withheld distinguish first synchronous attempt from later negotiation snapshots; confirmed means registry return, not native dispatch. DiPO capture can miss events older than its reader window; correlate WCP USB and available phone-side diagnostics using timestamps, with clock offset noted. Missing event is unknown. CPUL DiPO display profile remains based on local settings/API shape and listener readiness, not inferred phone preference or builder success.

CPUL has no Apple disabledFeaturesPreference read/write path. Local ultra_theme/ultra_sidebars toggles describe HU capabilities, not phone Ultra/Classic selection. A phone's explicit Classic choice must be respected; do not turn Ultra back on, delete phone preferences, force reconnect or automatically forget pairing. UI Sync production passes null wanted cluster and false forced center; production now neither reads nor writes the shared legacy layout/palette file. Recognized phone choices remain in connection-local memory and logs, not Apple feature preferences. The legacy file is left untouched and legacy fixtures retain their explicit persistence path. No production layout reissue. Wallpaper layout UUID/NoStyle blue and Midnight catalog assets are metadata, not proof of selection, asset download, transfer, installation or a wallpaper command. Do not force wallpaper. Virtual cluster receives/discards video, never renders on physical cluster, and STBT remains sole navigation owner. No new capability gates or transport behavior.

1. CPUL already synchronously contributes before its observer; its first attempt can follow WCP's appLoaded and fallback retry is ~2 s. Compare timestamps with first eligible StartSession dispatch; readiness/ADVERTISED is not dispatch. No duplicate sender, no forced repeat.
2. Existing pairing and fresh pairing may differ without a changed display recipe; preserve explicit Classic even when valid theme info exists. Please distinguish prompt-flow automatic opt-out from explicit user choice and unknown preference.
3. CPUL UI Sync uses a different application protocol and lane from demonstrated CarPlayUpdateData. Do not share message type numbers or conflate reset/ack with file accept. CPUL does not install cluster assets, and its tuple is not installation evidence.
4. Correlate redacted WCP StartSession actual dispatch, tuple provenance and prerequisites with CPUL initial contribution markers and DiPO display/stream evidence. If first eligible dispatch precedes registration, investigate provider lifecycle before proposing a change. The current source does not prove such a race occurs.
